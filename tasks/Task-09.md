# Task-09: Наблюдаемость, защита поверхности и эксплуатационная устойчивость

## Цель
Подготовить приложение к эксплуатации:
- метрики
- безопасное логирование
- защита от перебора
- безопасные заголовки
- контролируемый доступ к служебным endpoint'ам

## Результат
- Подключен Actuator
- Подключены метрики
- Логи не содержат секреты
- Есть базовый rate limiting
- Открытые административные и диагностические поверхности минимизированы

## Требования к Actuator
1. Разрешить только:
    - `health`
    - `info`
    - `prometheus` (опционально)
2. Запретить публичный доступ к остальным актуаторам.
3. `health` не должен раскрывать чувствительные детали.
4. Включить readiness/liveness probes при использовании контейнеров.

## Логирование
1. Запретить логирование тел запросов с секретами.
2. В логах не должно быть:
    - паролей
    - токенов
    - мастер-ключа
    - расшифрованных паролей учетных записей
3. Реализовать маскирование типовых чувствительных полей:
    - `password`
    - `token`
    - `secret`
    - `authorization`
4. Для ошибок возвращать обезличенные сообщения.

## Rate limiting
Добавить ограничение как минимум для:
- `POST /api/auth/login`
- `POST /api/auth/register` (если регистрация включена)

Минимальная реализация:
- in-memory limiter для одного инстанса

Если планируется горизонтальное масштабирование:
- указать, что нужен распределенный лимитер (например, Redis)

## Безопасные заголовки
Убедиться, что включены:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Cache-Control: no-store` для чувствительных ответов
- `Strict-Transport-Security` при работе за TLS-терминацией

## OpenAPI / Swagger
1. В dev-профиле можно оставить Swagger UI открытым.
2. В prod-профиле:
    - либо отключить
    - либо защитить административной ролью

## Метрики
Минимально:
- метрики Spring Boot Actuator
- при желании — Prometheus-совместимый экспорт

## Тесты
1. Проверить, что служебные endpoint'ы закрыты.
2. Проверить, что в логах нет секретов.
3. Проверить срабатывание лимитера на повторяющиеся попытки входа.
4. Проверить наличие безопасных заголовков.

## Критерии приемки
1. Приложение наблюдаемо.
2. Нет утечек чувствительных данных в служебных endpoint'ах.
3. Есть минимальная защита от перебора.
4. Логи безопасны.
