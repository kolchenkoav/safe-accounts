# Task-06: Администрирование, управление пользователями и ротация ключей

## Цель
Добавить административные функции и безопасную ротацию KEK.

## Результат
- Администратор может управлять пользователями.
- Есть операция перевода пользовательских DEK на новый активный KEK.
- Есть просмотр аудита.
- Все действия защищены ролью `ADMIN`.

## API

### Пользователи
Реализовать:
- `GET /api/admin/users`
- `POST /api/admin/users`
- `POST /api/admin/users/{id}/enable`
- `POST /api/admin/users/{id}/disable`
- `POST /api/admin/users/{id}/reset-password`

Требования:
- доступ только для `ROLE_ADMIN`
- пароль при сбросе задается новым значением
- при сбросе пароля отзывать все активные токены пользователя

### Аудит
Реализовать:
- `GET /api/admin/audit`

Требования:
- пагинация
- фильтрация по типу события, пользователю, периоду
- без раскрытия секретов

### Ротация ключей
Реализовать:
- `POST /api/admin/crypto/rewrap-deks`

Смысл операции:
1. Для всех пользователей, у которых `dek_kek_id` не совпадает с активным ключом:
    - распаковать DEK старым ключом
    - упаковать его новым активным ключом
    - обновить `dek_wrapped`, `dek_iv`, `dek_kek_id`
2. Операция должна быть идемпотентной.
3. Если старый ключ недоступен — операция должна завершаться с понятной ошибкой.
4. Событие ротации фиксируется в аудите.

## Требования к ротации
1. Поддержка сценария:
    - в конфигурации есть старый и новый ключи
    - новый ключ активен
    - старый ключ доступен только для расшифровки
2. После `rewrap-deks` все пользователи должны использовать новый активный KEK.
3. Запрещено логировать значения ключей.

## Права доступа
1. Все `/api/admin/**` требуют `ROLE_ADMIN`.
2. Обычный пользователь не может получить доступ к административным функциям.

## Аудит
События:
- `USER_CREATED_BY_ADMIN`
- `USER_RESET_PASSWORD`
- `USER_DISABLED`
- `USER_ENABLED`
- `KEY_ROTATION_STARTED`
- `KEY_ROTATION_COMPLETED`
- `KEY_ROTATION_FAILED`

## Тесты
1. Обычный пользователь не имеет доступа к админке.
2. Администратор может создать пользователя.
3. Отключение пользователя блокирует вход.
4. Сброс пароля отзывает старые токены.
5. Ротация ключей переводит DEK на новый активный ключ.
6. Расшифровка секретов после ротации продолжает работать.
7. Аудит содержит события административных операций.

## Критерии приемки
1. Администрирование работает.
2. Ротация ключей безопасна и идемпотентна.
3. После ротации данные остаются читаемыми для владельцев.
4. Все действия администратора логируются в аудит.
