# Task-05: CRUD API для сейфа

## Цель
Реализовать хранение, получение, изменение и удаление записей сейфа с шифрованием на уровне приложения.

## Результат
- Пользователь может управлять своими записями.
- Все чувствительные поля шифруются.
- Чужие записи недоступны.
- Есть аудит операций.

## API

### Список записей
`GET /api/vault`

Требования:
- пагинация
- сортировка по `createdAt`
- возвращать только метаданные и расшифрованные `site`, `login`
- пароль в списке не возвращать

### Создание записи
`POST /api/vault`

Тело:
- `site`
- `login`
- `password`
- `notes` (опционально)

Требования:
- все обязательные поля валидируются
- запись привязывается к текущему пользователю
- перед сохранением все поля шифруются

### Получение записи
`GET /api/vault/{id}`

Требования:
- по умолчанию пароль не возвращается
- при `?reveal=true` разрешается вернуть расшифрованный пароль
- доступ только для владельца
- факт `reveal=true` фиксируется в аудите

### Обновление записи
`PUT /api/vault/{id}`

Требования:
- обновлять можно только свою запись
- поля перешифровываются
- использовать оптимистичную блокировку
- изменение фиксируется в аудите

### Удаление записи
`DELETE /api/vault/{id}`

Требования:
- удалять можно только свою запись
- удаление фиксируется в аудите

## Требования к шифрованию
1. Перед сохранением шифровать:
    - `site`
    - `login`
    - `password`
    - `notes`
2. В БД не должно быть открытых значений.
3. Для расшифровки использовать DEK текущего пользователя.
4. Если расшифровка невозможна, вернуть безопасную ошибку без утечек.

## Требования к авторизации
1. Пользователь видит только свои записи.
2. Любой доступ к чужой записи возвращает `404` или `403` по единому безопасному стандарту.
3. Администратор не должен иметь неявный доступ к чужим секретам, если это не предусмотрено отдельной функцией восстановления (в первой версии лучше запретить).

## Валидация
- `site`: обязательное, длина до 2048
- `login`: обязательное, длина до 2048
- `password`: обязательное, длина до 4096
- `notes`: опционально, длина до 8192

## Аудит
События:
- `SECRET_CREATED`
- `SECRET_UPDATED`
- `SECRET_DELETED`
- `SECRET_REVEALED`

Запрещено писать в аудит:
- пароль
- примечание
- другие расшифрованные значения

## Тесты
1. Создание записи сохраняет в БД только шифрованные значения.
2. Чтение своей записи работает.
3. Чтение чужой записи запрещено.
4. Список не содержит пароль.
5. `reveal=true` возвращает пароль только владельцу.
6. Обновление перешифровывает данные.
7. Удаление работает и пишется в аудит.
8. Запись другого пользователя нельзя изменить/удалить.

## Критерии приемки
1. В таблице `vault_entries` нет plaintext-значений.
2. Все операции ограничены владельцем.
3. Ошибки безопасны и не раскрывают лишнего.
4. Аудит работает.
5. Интеграционные тесты проходят.
