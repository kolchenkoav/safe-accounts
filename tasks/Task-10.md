# Task-10: Сквозные тесты и контроль безопасности

## Цель
Проверить систему целиком и подтвердить, что реализованы ключевые свойства безопасности.

## Результат
- Есть сквозные интеграционные тесты
- Есть проверка изоляции пользователей
- Есть проверка, что БД не хранит секреты в открытом виде
- Есть чек-лист безопасности

## Обязательные сценарии e2e
1. Создать пользователя.
2. Выполнить логин.
3. Создать запись сейфа.
4. Получить список записей.
5. Получить детальную запись с `reveal=true`.
6. Обновить запись.
7. Удалить запись.
8. Проверить, что второй пользователь не имеет доступа к этим записям.

## Проверки безопасности
1. В таблице `vault_entries` нет plaintext-значений:
    - сайт
    - логин
    - пароль
    - примечание
2. В таблице `users` нет:
    - открытых паролей
    - открытых DEK
3. В таблице `auth_tokens` нет открытых токенов.
4. Отозванный токен не работает.
5. Пользователь с ролью `USER` не имеет доступа к `/api/admin/**`.
6. Ошибки авторизации не раскрывают лишнего.
7. Попытка получить чужую запись не приводит к утечке данных.

## Нагрузочные и устойчивые проверки (опционально)
- несколько пользователей одновременно
- параллельные операции создания/чтения/удаления
- проверка оптимистичных блокировок
- проверка поведения при недоступности БД

## Инструменты
- JUnit 5
- Testcontainers
- Spring Boot Test
- Spring Security Test
- AssertJ

## Архитектурные проверки (опционально)
Добавить ArchUnit:
- контроллеры не ходят в репозитории напрямую
- криптография не размазана по контроллерам
- сервисный слой не зависит от web-слоя некорректно

## Чек-лист безопасности
Сформировать `docs/security-checklist.md`:
- секреты не в коде
- секреты не в логах
- токены только в виде хэшей
- секреты в БД только зашифрованы
- доступ к чужим данным невозможен
- есть аудит
- есть резервные копии
- есть процедура ротации ключей

## Критерии приемки
1. Все сквозные тесты проходят.
2. Подтверждена изоляция пользователей.
3. Подтверждено отсутствие plaintext-секретов в БД.
4. Чек-лист безопасности заполнен и актуален.
