# Task-03: Криптографический модуль

## Цель
Реализовать безопасный модуль шифрования для работы с мастер-ключом, пользовательскими DEK и данными сейфа.

## Результат
- Есть `CryptoProperties`
- Есть `KeyManager`
- Есть `AesGcmCryptoService`
- Есть поддержка нескольких KEK
- Есть unit-тесты

## Функциональные требования
1. Поддержка мастер-ключей:
    - из `VAULT_MASTER_KEY_BASE64`
    - из `VAULT_MASTER_KEY_FILE`
2. Поддержка нескольких ключей:
    - `id`
    - `active`
    - `secret-base64`
3. Активный ключ должен быть ровно один.
4. Если активного ключа нет — приложение должно падать на старте.
5. Дешифровка должна поддерживать старые ключи, если они все еще заданы в конфигурации.

## Требования к шифрованию
1. Алгоритм:
    - `AES-256-GCM`
2. Длина ключа:
    - 256 бит
3. IV:
    - 12 байт
    - генерируется через `SecureRandom`
    - никогда не переиспользуется
4. Формат хранения:
    - Base64
    - внутри `iv || ciphertext || tag`
5. Для шифрования секретов использовать DEK пользователя.
6. Для хранения DEK в БД использовать wrapped-форму:
    - `wrappedDek`
    - `dekIv`
    - `kekId`

## API криптомодуля
Реализовать как минимум:
- `SecretKey generateDek()`
- `String encrypt(String plaintext, SecretKey dek)`
- `String decrypt(String encryptedBase64, SecretKey dek)`
- `WrappedDek wrapDek(SecretKey dek)`
- `SecretKey unwrapDek(WrappedDek wrappedDek)`

## Требования к конфигурации
Пример ожидаемой структуры:
- `app.crypto.keys[0].id`
- `app.crypto.keys[0].secret-base64`
- `app.crypto.keys[0].active`

И упрощенный режим:
- `app.crypto.master-key-base64`
- `app.crypto.master-key-file`

## Безопасность
1. Запрещено логировать:
    - значения ключей
    - расшифрованные секреты
2. Разрешено логировать:
    - `key id`
    - fingerprint ключа, если он не позволяет восстановить ключ
3. При ошибке расшифровки не раскрывать чувствительные детали.
4. В тестах использовать только тестовые ключи.

## Тесты
1. Шифрование/расшифровка строки.
2. Повторное шифрование одного текста дает разные результаты из-за IV.
3. Расшифровка неверным ключом падает.
4. Поддержка активного и старого ключа.
5. Отсутствие активного ключа приводит к ошибке старта.
6. Ошибка при ключе неверной длины.

## Критерии приемки
1. Все криптографические операции покрыты тестами.
2. Нет логирования секретов.
3. Модуль готов к использованию в сервисах пользователей и сейфа.
