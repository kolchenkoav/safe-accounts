# Task-11: Опциональный минимальный веб-интерфейс

## Статус
Опциональная задача. Выполняется только если нужен встроенный веб-интерфейс.

## Цель
Добавить простой внутренний веб-интерфейс для входа и работы с сейфом.

## Результат
- Есть страницы:
    - логин
    - список записей
    - создание записи
    - просмотр записи
    - изменение записи
    - удаление записи
- Интерфейс работает через серверные маршруты, а не через хранение токена в браузере

## Рекомендуемый подход
Использовать:
- **Thymeleaf**
- серверную сессию
- CSRF-защиту

Важно:
- Не хранить чувствительные токены в `localStorage`.
- Если используется браузерный интерфейс, предпочтительнее `HttpOnly` cookie и CSRF.
- Веб-часть должна быть отделена от API и не ломать текущую Bearer-аутентификацию.

## Функциональные требования
1. Страница входа.
2. Список записей текущего пользователя.
3. Создание записи.
4. Просмотр записи.
5. Редактирование записи.
6. Удаление записи.
7. Выход.
8. Сообщение об ошибке при неверных данных.

## Требования безопасности
1. Включить CSRF для веб-форм.
2. Пароли из форм не логировать.
3. Отображение пароля — только по явному действию пользователя.
4. Списки не должны показывать пароль по умолчанию.
5. Все действия должны использовать того же пользователя и те же правила доступа, что и API.

## Ограничения
- Не делать сложный SPA.
- Не хранить секреты в клиентском коде.
- Не делать интерфейс публичным без необходимости.

## Критерии приемки
1. Можно войти через браузер.
2. Можно создать/посмотреть/изменить/удалить запись.
3. Чужие записи недоступны.
4. CSRF защита работает.
5. Веб-интерфейс не ломает API.
