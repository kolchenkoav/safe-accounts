# Task-07: Docker, Docker Compose и секреты

## Цель
Упаковать приложение в Docker и подготовить воспроизводимый запуск вместе с PostgreSQL.

## Результат
- Есть многоэтапный `Dockerfile`
- Есть `docker-compose.yml`
- Приложение запускается в контейнере
- Секреты не попадают в образ и репозиторий
- Контейнер работает от непривилегированного пользователя

## Требования к Dockerfile
1. Многоэтапная сборка:
    - сборка через JDK
    - runtime через JRE
2. Использовать слоеный jar или эквивалентный механизм оптимизации.
3. Не копировать в финальный образ:
    - `.env`
    - секреты
    - исходники без необходимости
4. Запуск от отдельного пользователя без root.
5. Указать `EXPOSE 8080`.
6. Не задавать секреты через `ENV` в Dockerfile.

## Требования к docker-compose.yml
Реализовать сервисы:
- `db`
- `app`

### db
- image: PostgreSQL 16
- volume для данных
- healthcheck через `pg_isready`
- пароль БД через секрет или файл

### app
- сборка из `Dockerfile`
- переменные окружения:
    - `SPRING_PROFILES_ACTIVE=docker`
    - `POSTGRES_HOST=db`
    - `POSTGRES_DB`
    - `POSTGRES_USER`
    - `POSTGRES_PASSWORD` или файл секрета
    - `VAULT_MASTER_KEY_FILE` или `VAULT_MASTER_KEY_BASE64`
- depends_on с ожиданием готовности БД
- порт `8080:8080`

## Секреты
Поддержать два режима:
1. Простой локальный режим через `.env` (только для dev).
2. Более безопасный режим через Docker secrets или файлы в `/run/secrets`.

Требования:
- мастер-ключ не должен быть вшит в образ
- пароль БД не должен быть вшит в образ
- `.env` в `.gitignore`

## Entrypoint
Если используется файл секрета для пароля БД:
- entrypoint должен читать файл и экспортировать `SPRING_DATASOURCE_PASSWORD`
- после этого запускать приложение

Если используется файл мастер-ключа:
- приложение должно уметь читать `VAULT_MASTER_KEY_FILE`
- файл секрета должен монтироваться в контейнер

## Health checks
Минимально:
- `db`: `pg_isready`
- `app`: HTTP-проверка `/actuator/health`, если образ содержит нужный инструмент, либо альтернативная безопасная проверка

## Файлы для создания
- `Dockerfile`
- `.dockerignore`
- `docker-compose.yml`
- `docker-compose.override.yml` (опционально)
- `scripts/docker-entrypoint.sh` (если нужен)
- `secrets/.gitkeep` (или аналог)

## Критерии приемки
1. `docker compose up --build` поднимает БД и приложение.
2. Приложение успешно проходит миграции Flyway.
3. `/actuator/health` отвечает `UP`.
4. В образе нет реальных секретов.
5. Контейнер приложения не работает от root.
6. `.env` не попадает в git.
